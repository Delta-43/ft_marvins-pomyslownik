Written 2026-11-22 for the next session. Read this whole file, then `docs/FRONTEND-PLAN.md`, `DESIGN.md`, and look at the eight screenshots in `docs/design/flow-prototype/` before doing anything.

## 1. Ground truth and precedence

1. **Delta's flow prototype** is the ground truth for layout, content and behaviour: https://claude.ai/artifact/DHZBdffLN2rkdVEi6HGkNh. A copy with its data file and rendered screens is in `docs/design/flow-prototype/` (`prototype.html`, `cards.json` built from the live API, `desktop-*.png`, `phone-*.png`, `render.mjs` to re-render). The artifact's motion spec is also summarised in `DESIGN.md` §7.
2. **Philip's brief** adds two things to the landing: the sign-in panel is a floating card on the right, and the left half carries animated content that fades through features and goals.
3. **Colour comes from Delta's `DESIGN.md`** (now v2.0, palette with measured contrast). Nothing else from the previous frontend carries over.
4. Mentor feedback (`docs/MENTOR-FEEDBACK-2026-11-22.md`) applies where it does not contradict 1 and 2: three languages, WCAG 2.2, ARIA, three actions to the first card.
5. The contract is `docs/api/openapi.yaml` 1.1.0-draft.5. The live API (`https://demo.delta43.net`) still returns `{pl, en}` text objects and ignores `Accept-Language`; `relatedWork` is empty; `demoIdentities` is not sent. Details in `docs/FRONTEND-PLAN.md` §1.

## 2. What happened before this handoff

- Branch `rebuild/frontend` was cut from `origin/main` (commit `5206565`). The working tree holds an **uncommitted** rebuild of `frontend/src` (about 45 files) that typechecks and runs, but it reproduces the previous frontend's look (colour field, glass header, search page with presets and stats, two-column tiles, a separate card page) and only takes the motion from the artifact. Philip rejected it: "You just built the same page again." Treat it as a parts bin, not a base. Reusable as-is: `src/lib/api.ts` (Accept-Language, `text()` fallback), `src/lib/settings.ts` (display settings cookie), `src/lib/compare.ts`, `src/lib/results-url.ts`, `src/app/actions/*` (sign-in with the opening result, register, events with the contract's type names, profile), `src/i18n/*` (pl, en, uk), `messages/{pl,en,uk}.json` (377 keys; Ukrainian is machine-translated, task R12), `src/components/motion/Motion.tsx` and the "Motion" block in `globals.css` (native view-transition names keyed on the navigation type; the only approach that works under Next's streamed segments, see the comment in Motion.tsx), `src/components/Logo.tsx`.
- Three reviews of that build exist and their findings still apply to whatever is built next:
  - **impeccable / better-ui** (27/40): hover styles must sit behind `@media (hover: hover)`; the phone header overlapped the logo with the demo badge; a compare basket must not cover content when empty; one type scale (`text-small`/`text-caption`, never Tailwind `text-sm`/`text-xs`); shadow or border, not both; tokens instead of hex literals; `::view-transition-image-pair(search-bar) { isolation: isolate }`.
  - **better-accessibility**: never render a form twice (duplicate ids broke labels and the sort submit); no `role="tab"` without the APG keyboard pattern; a submit must give feedback, never silently do nothing; `scroll-padding-bottom` under a sticky bottom bar; auto-moving backgrounds need a pause or must stop within 5 s; registration errors bound to their fields with `aria-invalid` and focus; `role="status"` for info, `role="alert"` for errors only; `role="list"` on styled lists; no `outline-none` on `main`.
  - **improve-animations**: the reduced-motion rule must keep 120 to 160 ms cross-fades, not kill all animation; the phone filter sheet needs transitions (open and close, backdrop fade, `@starting-style`); hero panels must cross-fade with overlap, not blank then fade; no `transition-all`; press feedback 100 ms at `scale(0.985)`; no `scale()` on blurred backgrounds; evidence disclosures and the phone menu deserve a 180 to 220 ms reveal.
- PR #32 (branch `Philip`) holds the earlier motion work on the old design. It is not merged and not needed.

## 4. How to work

- Keep every page a server component on the real API; plain forms and links, JavaScript only adds the moves. One primary action per screen.
- Build the four templates in one commit before anything else and screenshot them with headless Chrome (`/Applications/Google Chrome.app/Contents/MacOS/Google Chrome --headless=new`), the way `docs/design/flow-prototype/render.mjs` does.
- The user's dev server runs on port 3000 from this working tree; do not start a second one.
- Demo sign-in: `POST /api/v1/auth/login` with `provider: sandbox_id`, `providerSubject: demo-jury`. Signing out in a test invalidates that token.
- Commit on `rebuild/frontend` only when Philip asks; open a PR to `main` when done (see `TASKS.md` working rules).
